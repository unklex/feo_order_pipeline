# ФЭО: заказы ФГИС ОПВК → MySQL → Битрикс24

Выгружает заказы на транспортирование из ФГИС ОПВК (gisopvk.ru), хранит их в MySQL (`fgis_feo`)
и создаёт/заполняет/обновляет карточки смарт-процесса ФЭО (137) в Битрикс24.

## Установка

Зависимости ставит [uv](https://docs.astral.sh/uv/) (`pyproject.toml` + точные версии в `uv.lock`):

```powershell
git clone https://github.com/unklex/feo_order_pipeline.git
cd feo_order_pipeline
uv sync                       # создаст .venv и поставит пакеты (при необходимости и Python 3.13)
Copy-Item .env.example .env   # затем заполнить .env
```

После `git pull` достаточно снова выполнить `uv sync`. Новый пакет: `uv add <пакет>` (обновит
`pyproject.toml` и `uv.lock` — их коммитить). Нужен Google Chrome (вход на gisopvk.ru).
Во внутренней сети: `DB_USE_SSH=0`, `DB_HOST=<внутренний IP сервера БД>`; снаружи — `DB_USE_SSH=1` и `SSH_*`.

## Работа через UI

```powershell
uv run streamlit run app.py
```

Откроется http://localhost:8501:

- **Добавить и заполнить** — новые заказы: выгрузка → импорт в БД → карточки в Битрикс → заявки из ФГИС →
  заполнение карточек → статусы. Заявки, которые распарсены, но не заполнены, запрашиваются заново.
- **Обновить статусы** — выгрузка → статус, история, сумма и транспортные задачи в карточках.
  Галочка «Не скачивать заново» берёт последнюю выгрузку.
- **Войти в ФГИС** — откроет Chrome; после входа на gisopvk.ru окно закроется само, cookies сохранятся.
  Нужно, когда запуск остановился с «Нужен вход в ФГИС».
- Вкладки **Данные** (сколько заказов на каком этапе, статусы в выгрузке) и **Журнал Битрикс**
  (что и в какие карточки отправлено, ошибки, ссылки на карточки).

Запуск идёт отдельным процессом: закрытие вкладки его не прерывает.

## То же из консоли

```powershell
uv run login_fgis.py                    # вход в ФГИС (если просрочен)
uv run pipeline.py add                  # новые заказы целиком
uv run pipeline.py statuses             # статусы
uv run pipeline.py statuses --skip-download
```

Код выхода: 0 — успех, 3 — нужен вход в ФГИС, 1 — ошибка. Если шаг выполнен, но часть карточек или
заявок не обработана (код шага 4, в UI — ⚠️), следующие шаги всё равно выполняются, а запуск
завершается с ошибкой: подробности — в журнале запуска и во вкладке «Журнал Битрикс».
Для ежедневного запуска статусов —
Планировщик заданий Windows: программа `.venv\Scripts\python.exe`, аргументы `pipeline.py statuses`,
рабочая папка — папка проекта.

Отдельные шаги можно запускать как раньше, через `uv run` (с вопросами в консоли): `0_step0_get_orders.py`,
`1_step0_1_import_to_db.py`, `new_2.1_sync_orders_transportation.py`, `1_step0_2.1_collects_bids.py`,
`fill db.py`, `update_orders_daily.py`, `status_history.py`.

Оба сценария последним шагом загружают историю статусов из выгрузки в таблицу `order_status_history`
(`status_history.py`; таблица создаётся при первом запуске, повторная загрузка той же выгрузки
ничего не дублирует). По ней считаются время на этапах и возвраты на доработку.

Когда ФГИС пересоздаёт транспортирование, у заявки появляется новый ID, а старое уходит в служебную
заявку со статусом old. Импорт переводит строку заявки (и её карточку) на новое транспортирование,
сбрасывает «загружена/заполнена», чтобы карточку заполнили заново, а старый ID записывает в
`replaced_transports` — отдельной заявкой и карточкой он не заводится.

Структура API ФГИС (поля эндпоинтов, какие sort/фильтры/include работают, время ответа) — `uv run api_probe.py` или кнопка «Исследовать API» на вкладке **API ФГИС**, только чтение; отчёт в `reports/api_probe_<время>/report.md` (там же скачать md/json/zip).

Телеметрия (история точек ТС) — вкладка **Телеметрия** в UI или из консоли, только чтение:

```powershell
uv run telemetry_download.py --from 2025-01-01 --out D:	elemetry_full --dry-run   # подсчёт
uv run telemetry_download.py --from 2025-01-01 --out D:	elemetry_full             # выгрузка
```

Точки — `telemetry_<время>.csv.gz` в папке, плюс `summary.csv` и `vehicles.csv`. Повторный запуск докачивает только недостающее (в т.ч. после истёкшего входа или остановки). Заменяет `telemetry_export.py` + `opvk-export.exe`: тот же API и те же окна, exe не нужен.

Списки целиком (водители ЭКОПРОМ, ТС, транспортные задачи, договоры, лицензии) — вкладка **Выгрузки** или `uv run api_export.py drivers` (свой адрес: `--url https://gisopvk.ru/webapi/v1/…/`). Результат — `exports/<имя>_<время>/records.csv` (Excel) и `records.jsonl.gz`; в git не попадает (личные данные).

Тесты: `uv run pytest`.

## Файлы

| Что | Где |
|---|---|
| Полная выгрузка заказов | `gisopvk_webapi_<дата>_<время>_1-<N>.jsonl.gz` в папке проекта (остаётся последняя) |
| Распарсенные заявки, ждущие заполнения | `batch_*.json` в папке проекта |
| Отработанные выгрузки и заявки | `archive/<ГГГГ-ММ-ДД>/`, удаляются через `ARCHIVE_KEEP_DAYS` (30) дней |
| Журналы запусков | `logs/pipeline_*.log`, `logs/pipeline_state.json` |
| Журнал вызовов Битрикс | `logs/audit_<скрипт>_<время>.jsonl` (одна строка — одно событие) |

`.env`, cookies, выгрузки, заявки, архив и журналы в git не попадают (см. `.gitignore`).
